## 第 12 章：为什么是 `#141414`：中性深灰与纯黑之辩

### 12.1 纯黑（`#000000`）的三大物理缺陷

在暗色模式兴起之初，许多应用简单地将背景设为绝对纯黑（`#000000`）。在实际人机工效学中，这造成了三大致命问题：

1. **OLED 像素点亮延迟（OLED Smearing / Purple Ghosting）**：
   在 OLED/AMOLED 屏幕上，`#000000` 意味着像素完全关闭。当高对比度元素在纯黑背景上滚动时，关闭的自发光子像素需要数十毫秒重新激活，会在边缘拉出难看且令人眩晕的**紫色/黑色拖尾残影**。
2. **消灭了深度层级（Elevation Death）**：
   在现实世界中，阴影必须比表面更暗才能被感知。如果背景已经是 `#000000`，所有下层阴影（Drop Shadow）全部失效，卡片悬浮感彻底归零。
3. **对比度压迫与视觉疲劳（Contrast Glare）**：
   纯白 `#FFFFFF` 在纯黑 `#000000` 上的对比度高达 21:1，在暗室环境下会产生强烈的眩光刺眼感，加速视疲劳。

### 12.2 Tuff 的三层深灰空间阶梯

Tuff 选定 `#141414`（极深温和碳灰）作为画布基底，并建立了严格的物理级差：

| 层级 | 色值 | 物理隐喻 | 典型应用 |
|---|---|---|---|
| **L0 底板** | `--tx-bg-color: #141414` | 吸收一切杂光的深空 | 桌面窗体底板、全局空白区 |
| **L1 卡片** | `--tx-fill-color-blank: #1c1c1e` | 带有微弱漫反射的哑光表面 | 设置项卡片、表格行、侧边栏容器 |
| **L2 悬浮** | `--tx-fill-color-light: #252528` | 吸收环境漫射光的凸起物 | Hover 悬停态、选中项高亮、浮动操作栏 |
| **L3 顶层** | `--tx-fill-color-lighter: #2f2f32` | 贴近视网膜的最高层级 | Popover 菜单、Tooltip 气泡 |

这种级差保留了阴影投射的空间可能，同时彻底消除了 OLED 屏幕滚动时的黑斑拖尾。

## 第 13 章：暗色模式视网膜光晕效应与字重视觉补偿

### 13.1 视网膜光渗效应（Optical Irradiation Illusion）

早在 1867 年，生理光学先驱赫尔曼·冯·亥姆霍兹（Hermann von Helmholtz）就在《生理光学手册》中记录了这一感知现象：
**视网膜上的感光细胞受强光刺激后，兴奋会扩散到相邻的暗区细胞，导致亮区在视觉上向外膨胀**。

```
浅色模式 (黑字白底):
字体黑色吸收光线，周围白底发光挤压黑色边缘 -> 笔画显得紧凑、清晰、偏细。

暗色模式 (白字黑底):
白色笔画发光向外扩散，浸润周围暗黑背景 -> 视觉上笔画膨胀 10% ～ 15%！
```

这也是为什么同一个 `font-weight: 500` 的按钮，在暗色模式下常常显得“笨重”、“傻粗”和排版粗糙。

### 13.2 字重梯度的双主题校准

为了在深浅两种模式下获得完全一致的粗细感知，前沿产品（如 Claude Desktop）会利用现代可变字体（Variable Fonts）的无级调节能力，对暗色字重进行微小下调：

| 文字角色 | 浅色模式（Light）标准 | 暗色模式（Dark）补偿 | 视网膜感知匹配度 |
|---|---|---|---|
| **正文默认** | `400`（Regular） | `380` ～ `400` | 完全匹配（消除白字膨胀） |
| **微强调** | `500`（Medium） | `460` | 柔和微强调，不糊成团 |
| **小标题/按钮** | `600`（Semi-Bold） | `560` | 清晰挺拔，笔画内腔不闭合 |
| **大标题** | `600` / `700` | `580` / `650` | 保持稳固骨架 |

### 13.3 离散字体回退的安全防线

**严肃工程陷阱**：在 CSS 中写下 `font-weight: 460`，只有当系统字体支持可变字重轴（如 macOS 的 `-apple-system` San Francisco、Windows 的 Segoe UI Variable、`Inter Variable`）时才会真正生效！
如果环境回退到了不支持可变字重的静态中文字体（如部分 Linux 发行版的思源黑体静态分包）：
* `460` 落在 `400～500` 区间内，浏览器会根据回退算法将其向上就近匹配到 `500`！
* 这不仅没有减轻膨胀，反而**进一步加粗了文字**！

TuffEx 的防异化工程解法：

```scss
// 仅当确定存在可变字体支持时启用精确数值，否则降级为调整透明度对比度
@mixin tx-adaptive-weight($light-weight: 500, $dark-weight: 460) {
  font-weight: $light-weight;

  [data-theme="dark"] &,
  .dark & {
    // 支持高级变体时微调字重
    @supports (font-variation-settings: "wght" 460) {
      font-weight: $dark-weight;
    }
    // 静态字体环境下：保持 400/500，通过降低文字色阶亮度来抵消光晕膨胀
    @supports not (font-variation-settings: "wght" 460) {
      color: var(--tx-text-color-regular); // 替代过于刺眼的 primary pure white
    }
  }
}
```

## 第 14 章：双极性语义着色与 `color-mix` 墨水融合

### 14.1 传统暗色色相崩塌的根源

许多传统 UI 库在浅色模式下定义了柔和语义色（如危险红的淡背景 `-light-9` 为 `#fef0f0`）。在暗色模式下，如果机械地按比例加白，该背景会变成一块刺眼的白斑；而如果机械按比例压黑，又会变成毫无活力的脏褐色。

### 14.2 TuffEx 的墨水融合方程式

TuffEx 在 2026-09-24 确立了语义墨水与背景的数学融合规则：
**彩色文本墨水绝不使用孤立的原生纯色相，而是将该色相与环境主墨水（Primary Ink）在 sRGB 空间进行严格混色**：

```scss
// TuffEx 跨主题 4.5:1 对比度守恒混色公式
color: color-mix(
  in srgb, 
  var(--tx-color-danger, #f56c6c) 55%, 
  var(--tx-text-color-primary, #303133)
);
```

#### 实测对比度守恒表（13px 文本）

| 语义色 | 纯色相在 `-light-9` 背景上的对比度 | `color-mix` 优化后的实测对比度 | 达标判定（WCAG 4.5:1） |
|---|---|---|---|
| **Danger (危险)** | 2.61:1（严重违规，看不清） | **4.78:1** | **PASS（清晰易读）** |
| **Success (成功)** | 2.08:1（惨白不可读） | **4.58:1** | **PASS（清晰易读）** |
| **Warning (警告)** | 2.03:1（黄褐色脏斑） | **4.62:1** | **PASS（清晰易读）** |
| **Info / Primary** | 2.53:1（发灰） | **4.81:1** | **PASS（清晰易读）** |

## 第 15 章：加色与减色混合：深浅主题的光学裂变

### 15.1 为什么加色光发（Plus-lighter）在浅色模式是灾难？

在暗色模式下，多个发光光束（如 `TxPrismGlow` 棱镜光效、AI 响应光芒）通过加色模式叠加：
$$\text{Color}_{\text{Result}} = \min(1, \text{Color}_A + \text{Color}_B)$$
光线叠加趋近于纯白高亮，呈现出如同霓虹灯在夜色中交汇的梦幻通透感。

**然而在浅色模式（白底）下：**
白色画布的 RGB 已经接近 `(1, 1, 1)`。加色模式不仅无法加出更亮的高光，两个色相相差大于 120° 的半透明层（例如蓝色与黄色）在浅色底板上平均后，会直接坍塌成**肮脏的暗灰色污渍**！

### 15.2 双重色相相位隔离（Dual Hue Ordering）

TuffEx 的核心光效组件（如 `TxPrismGlow`）在底层构建了深浅两套完全独立的色相循环管道：

```ts
// packages/tuffex/packages/components/src/prism-glow/src/cones.ts
export const DARK_HUE_ORDER = [0, 60, 120, 180, 240, 300]; // 暗色：全色域发散，交织融合向白光

export const LIGHT_HUE_ORDER = [210, 230, 250, 190, 220]; // 浅色：限定在相邻冷色调区间（<60°）
// 绝对禁止在浅色模式下让补色（如蓝与橙）同时启动，确保叠加强度永远维持在纯净透亮区间
```

## 第 16 章：无障碍对比度工程：WCAG APCA 与 4.5:1 铁律

### 16.1 13px 正文严禁使用 `secondary` 墨水

很多设计人员喜欢大面积使用副文本颜色（`--tx-text-color-secondary`）来追求界面的“灰调高级感”。
在标准测量下：
* `--tx-text-color-secondary` 在白底上的对比度仅为 **3.08:1**！
* 在浅灰底板上的对比度甚至暴跌至 **2.87:1**！

**TuffEx 强制规范**：
* 凡是需要用户阅读、识别的正文内容、列表文本、表单标签，**必须使用 `--tx-text-color-regular`（实测 5.69:1）或 `--tx-text-color-primary`**。
* `secondary` 仅允许用于非必要辅助说明（如最后同步时间、极淡占位符）或纯图标（图标仅要求 3:1）。

### 16.2 禁止单纯依靠颜色传递状态

色盲与色弱群体（如红绿色盲）在全球男性中占比超过 8%。
**铁律：所有语义状态（成功、危险、加载中、离线）必须遵循“色相 + 图标形态 + 文字标签”的三重互锁**。

```html
<!-- 错误写法：单纯依靠红点传达离线，红绿色盲用户完全无法识别 -->
<span class="status-dot red"></span>

<!-- 正确写法：图标几何形态不同，并配合无障碍属性与文字 -->
<span class="tx-badge tx-badge--danger" role="status" aria-label="服务离线">
  <TxIconCross aria-hidden="true" />
  <span>服务已中断</span>
</span>
```

## 第 17 章：高对比度模式与系统级偏好响应

### 17.1 组件内部零 Hex 字面量

在 TuffEx 组件源码中，**写入任何硬编码十六进制颜色（如 `#ffffff`、`#333333`）均被静态检查视为致命 Defect**。

所有颜色必须经由 `--tx-*` 令牌流转，这使得系统可以零成本响应系统级高对比度模式：
* 浅色高对比模式（`tx-high-contrast-light`）：边框强化为纯黑 `#000000`，背景纯白 `#ffffff`，移除所有半透明度与磨砂折射。
* 深色高对比模式（`tx-high-contrast-dark`）：反差边界达到最大，主色调自动换用经过无障碍强化认证的高亮度安全色。
